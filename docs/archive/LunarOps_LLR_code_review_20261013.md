# LunarOps 已实现模块全面审计与精简整改建议

**版本**：1.0 · **日期**：2026-10-13 · **交付性质**：静态代码审计、针对性隔离验证、外部软件对标、修改说明（不含任何已修改源代码）

**审计对象**：`lunarops_code_review_20261013.zip` 的工作树快照。本文的“应删除”均指未来经测试后实施，不表示已修改上传的软件。

## 1. 总体结论与决策原则

当前软件已经具备相对清晰的 `config → programs → observation/dynamics/estimation → fileio` 分层，能够从原始法点走向测距、可见性预报、几何参数平差，以及月球轨道与自转积分。真正需要优先纠正的并非“模型功能太少”，而是**格式入口的健壮性、科学语义的显式性、配置与数据的可追溯性**。一些保护分支是科学正确性必需品；将它们一律视为兜底删除会造成严重回归。

**本轮最重要的审计判定：**

- **P0：源码当前不可整体通过 Python 语法解析。** `fileio/formats/crd.py` 与 `fileio/normal_points.py` 存在未加括号的多异常捕获；前者有三处，后者有一处。任何后续数值回归都应先过编译和导入质量门槛。
- **P1：观测格式语义可能被错误归一化。** CRD 记录 11 含 epoch-event 字段，但导入器忽略它，直接解释为地面发射时刻；CRD bin RMS 与单法点测距不确定度的概念亦不能不经说明即等同。
- **P1：动力学重力场文件存在静态/时变语义混淆。** 当前 ICGEM 读取把 `gfct` 当普通 `gfc` 读取，却不处理相应时段与 `trnd/asin/acos`，也没有拒绝时变模型。
- **P1：缓存/续跑指纹不覆盖星历目录内容。** 已在隔离试验中复现：目录内内核文件内容变了，`scientific_fingerprint` 仍保持相同值；引用具体文件时才随内容变化。
- **P1：个别兜底会改变科学定义。** EOP 解析的猜格式与缺失项补零、轨道力项自动开启、预报气象常数默认，以及 TT→TDB 迭代超限仍返回值，均应整改为显式声明、拒绝输入或带可审计状态的策略。
- **值得保留：** 正规方程秩亏显式报错；光时不收敛状态与 O−C 诊断；EOP 超出覆盖范围拒绝插值；数值积分历史、缓存与严格时标接口；平差终止原因、权因子、秩与协方差输出。

### 1.1 三种动作，而非“全部删光”

| 动作 | 判定标准 | 处理方式 |
|---|---|---|
| **删除（D）** | 无真实使用方的别名、重复调用路径、无物理含义的猜测与宽松兼容 | 先查引用与回归，再删除；不保留永久兼容层 |
| **替换（R）** | 表面兜底实为科学决策，直接删会破坏已有合法输入 | 替换为严格模式/明确配置/版本化输入合同，并记录元数据 |
| **保留（K）** | 保障数值稳定、数据完整性、失败显式化、并行资源正确生命周期 | 保留，可整理接口与文档，但不能牺牲诊断 |

“完全一致”只适用于不改变科学语义的纯结构精简；修复已经确认的语义问题应按**受控科学变化**记录新的基线，而不是为了重现旧结果放宽门槛。

## 4. P1：LLR 测距模型与观测数据处理

### B-02【P1 / R】CRD epoch-event 不可被忽略

**定位**：`fileio/formats/crd.py:16–24,190–216,263–278,296–336`。**证据：事实 + 标准佐证 [R9]。**

**现状**：文件头注释明确声明忽略 CRD 记录 11 的 epoch-event，所有历元直接填入 `transmit_epoch`。而 ILRS CRD v1/v2 的 11 记录含“Epoch event”字段；接收、反射及发射事件的时刻不是同一件事。只要实际输入中不是发射时刻，就不能这样无条件解释。

**修改要求**：在 CRD 适配器建立 **仅允许支持的事件类型并明确映射** 的入口合同：如果只支持地面发射时刻，应拒绝其他代码并给出行号/事件代码；如要支持转换，须有明确的时标与光时关系，并单独校核，不能从文件名猜事件。导入报告保留源事件类型和拒绝原因。绝不可“默认当作发射事件”作为兼容策略。

**验收**：构造 11 记录的发射/接收/反射事件样本；已支持类型输出正确事件语义；未支持类型必定报明确错误或进入结构化拒绝清单；没有静默几秒级错位。

### B-03【P1 / R】CRD 气象时间戳的“失败当零”和无限最近邻

**定位**：`fileio/formats/crd.py:219–228,257–260,305–323`。**证据：事实。**

**现状**：`seconds_of_day=_to_float(fields[1]) or 0.0` 将无法解析和合法午夜 `0.0` 合并；气象记录随后按一天周期的“最近秒数”匹配，不设最大时间差，亦无气象记录所在具体日期。跨午夜或长会话时可能把过时或错误气象数据当成当时观测条件。

**修改要求**：删除 `or 0.0` 兜底；气象记录无效须记行号并隔离；在会话起止日期约束内生成绝对 UTC 气象时刻；明确最近邻最大时差、缺测策略及允许的跨午夜行为。选择最近邻还是插值应由物理设计固定并纳入结果元数据。

**验收**：坏的 20 记录秒数被拒绝；23:59/00:01 两个时刻配对正确；超时窗数据拒绝；处理计数符合 `输入=有效+拒绝`。

### B-04【P1 / R】CRD 的 bin RMS 不等同于无条件认可的法点 σ

**定位**：`fileio/formats/crd.py:21–24,190–216,334–336`；`classes/observation/normal_points.py:58–65`。**证据：事实 + 物理含义需验证 [R9]。**

**现状**：当前将 record 11 的 `bin_rms`（ps）直接作为 `uncertainty_two_way_s`，进入几何参数平差权矩阵。标准对该字段的定义是 accepted raw time-of-flight 相对均值的 bin RMS；它与特定处理链所需“法点均值的不确定度”之间的关系需要验证，不能无条件等同，更不能未经依据统一除以√N。

**修改要求**：区分“原始观测质量量”“用于权的后验/先验 σ”；将权的解释规则、出处及单位写入格式合同和输出元数据；对于不能由 CRD 唯一确定的 σ，优先拒绝参与正式估计或要求显式外部精度模型。任何变更都必须重做平差权、WRMS、σ0 与协方差回归。

**验收**：针对一条有权威解释的 ILRS 记录，逐字段核对源记录、两程时间标准差、单程米转换、入权 σ；不同定义的测试用例不可混用。

### B-05【P1 / R】MINI 温度单位仍有已记录歧义

**定位**：`fileio/formats/mini.py:48–52,207–214`。**证据：事实（源码已在注释中承认歧义）。**

**现状**：读取程序按 0.1 °C 转换，但源码注释指出部分 MINI 文档将该字段描述为 0.1 K。若数据批次来源/版本不同，此差异直接影响 Mendes–Pavlis 大气延迟。

**修改要求**：先核对使用中的原始 MINI 样例及发布规范，明确支持的变体；不得根据数值大小“智能猜单位”。如确有多版本，使用文件版本/来源或显式配置分支，并把选择写入转换产物和日志；如果只有一种权威定义，就删除与它不符的备用解释、在测试中锁定。

**验收**：0 °C 与约室温场景源字段/输出 K 值正确；错误版本配置拒绝；O−C 对单位变化的影响有独立对比。

### B-06【P1 / R】CRD 会话、系统配置与输入质量校验须可证明

**定位**：`fileio/formats/crd.py:156–188,190–230,296–319`；`fileio/formats/normal_point_sources.py:93–107`。**证据：事实 + 条件风险。**

**现状**：`crd_version = _to_int(...) or 1` 在头标坏值时默认为 v1；11 记录的配置 ID 没与 C0 对应校验；H4 仅将秒数映射到“起始当天或次日”；一些少字段头记录可能直接 `IndexError`。此外，读取文本 `errors="replace"` 会隐藏字节编码故障。

**修改要求**：版本应严格由合法 H1 决定；建立逐行状态机，检查 header/C0/H4/11/20 及会话边界；匹配波长配置 ID、时标事件类型与有效时段；对必要的编码错误拒绝而不是替换字符；保持原始行号及跳过比例。保留 CRD v1、v2 两个明确的解析分支，不建立“所有异常格式也试一试”的模糊链。

**验收**：缺 H1/H2/H4/C0、未知配置 ID、坏日期、坏浮点、跨多日、gzip 损坏分别给出可定位诊断；所有通过的记录保留可溯源输入标识。

### B-07【P1 / K+R】光时迭代保留收敛标志，但要验证双腿事件闭合

**定位**：`classes/observation/light_time.py:521–527,572–698`；`classes/observation/prediction.py:140–145`。**证据：需验证；不构成已发现数值错误。**

**现状**：双程迭代以 RTT 变化作为停止量；迭代状态同时包含反射与接收历元。虽然 RTT 停止通常足以收敛，但两条腿的独立事件闭合尚需在测试中明确；预报已经在不收敛时报错，测距状态也能输出不收敛标志，这是优点。

**修改要求**：保留 `light_time_converged`、迭代次数与失败行；在验收中分别验证 `t2−t1=τup`、`t3−t2=τdown`、`t3−t1=τup+τdown`，并检查末次计算的物理延迟对应同一事件时刻。若测试证明仅 RTT 差不足，才在受控算法变更中把两腿残差加入停止条件；不能仅为了简化而取消任何收敛状态。

**验收**：正常几何、高/低仰角、不同星历、年代边界与人为不收敛样例均输出正确事件闭合指标和状态。

### B-08【P1 / R】低仰角对流层截断应成为可见策略而非默许有效

**定位**：`classes/observation/light_time.py:437–443,495–505,610–615`；`classes/observation/measurement.py:240–256`。**证据：事实。**

**现状**：对流层模型可把物理仰角截到 `elevation_floor_rad`；代码已有 `troposphere_elevation_clamped` 指标。这是避免公式奇异的保护，不应简单删除，但物理上不能把截断值当真实低仰角观测。

**修改要求**：将允许低仰角截断、拒绝低仰角、仅供预报的策略显式化；正式测距/估计运行报告每类截断次数、观测 ID、使用仰角，不允许把受截断严重影响的观测悄悄当作高质量数据。

**验收**：截断出现时报告非零且原始仰角不丢失；低于业务截止角的观测不会混入正式解；边界角度精确测试。

### B-09【P2 / K】观测对象的数值有效性校验值得保留

**定位**：`classes/observation/normal_points.py:28–55`；`classes/observation/prediction.py:38–57,84–94`。**证据：事实。**

**现状**：时间尺度、正值、有限数值、湿度范围、能见度阈值均有检查。建议保留这些约束；精简时不要把“输入层已验证”误解成“所有运行时接口永远只会接收合法对象”。可以将重叠的错误说明与边界判断集中到构造入口，但不取消物理量类型校验。

**验收**：NaN、Inf、负 RTT/σ/波长、非 UTC 法点与异常湿度仍被阻止进入物理计算。

## 5. P1：时标、地球定向、参考框架与位移延迟

### B-10【P1 / D+R】IERS C04 解析不应靠“猜 MJD 在第几列”

**定位**：`classes/frames/earth_orientation.py:421–507`。**证据：事实。**

**现状**：有常见 C04 形式、带小时形式、简化 MJD 开头形式和 “Last-resort MJD discovery” 通用扫描；后一种甚至允许非 IERS 表格只要某处数值恰像 MJD 且后面三列似极移/UT1，就被接受。多个格式猜测与容许量阈值组合不等于格式正确性。

**修改要求**：删除最后的盲扫支路；为确实需要的 C04 14、C04 20（及已使用的小时扩展）分别定义受支持列布局和版本识别；用列数、日期/MJD 一致性、单位、字段完整性验证代替物理量范围“看起来合理”。不支持的第三方派生表格必须先显式转换再输入。

**验收**：IERS 官方逐格式样例通过；前面添加假 MJD 数字、错位一列、日期不匹配样例全部被拒绝；旧合法历史 C04 样本不得被无意丢弃。[R3][R10]

### B-11【P1 / D+R】EOP 缺字段补零、吞乱码、跳过坏行，破坏数据质量可见性

**定位**：`classes/frames/earth_orientation.py:453–479,510–574,353–360`。**证据：事实。**

**现状**：缺失 `dX/dY/LOD` 在解析时补 0；`read_text(errors="ignore")` 丢弃非法编码字节；读取时通过 `if sample is not None` 直接忽略未解析行；计算早期日期 `erfa.dat` 的警告被一律忽略。这些在“科学字段本来为零”和“此字段并未提供”之间造成歧义。

**修改要求**：区分官方确实缺省字段的合法格式和坏行；用带缺测掩码/质量状态的样本表示，或声明缺测字段不能用于对应模型；拒绝不可识别的非注释内容并统计行数；不要全局吞掉 ERFA 日期/精度警告，而按已知良性类别显式解释。只保留有来源说明的填零行为。

**验收**：真实零与缺值可区分；坏行和编码损坏不能默默减少样本；早期/现代年代时差及警告可查；EOP 超范围仍应报错（现已做到，必须保留）。

### B-12【P1 / R】EOP 合并后失去 final / rapid / prediction 的逐样本来源

**现状**：`filter_time` 对 `self.records` 重新赋值并对记录重新编号；`combine_npt_datasets` 也直接修改输入 `record.index`。若同一个 dataset 被缓存/多个工作流复用，改变了调用者可见的源状态。

**修改要求**：考虑将规范化后的原始法点视为不可变观测事实，筛选与合并返回新的容器/新索引映射；如为性能保留可变对象，则明确声明是破坏性操作，仅允许在 I/O 入口的单一拥有者作用域内使用，不应作为公共透明 API。

**验收**：输入 dataset 在筛选、合并前后的记录与 ID 不改变（若选择无副作用方案）；跨重叠窗口结果不互相污染；MPI 序列化后观测 ID 稳定。

### B-30【P2 / D+R】输入类型识别的文件后缀与内容探测顺序应唯一

**定位**：`fileio/formats/normal_point_sources.py:93–107`；`fileio/formats/crd.py:69–87`；`fileio/formats/mini.py:114–138`。**证据：事实。**

**现状**：有 native、CRD、MINI 三路识别；CRD 的已知后缀即自动判定，而另一条路径尝试读取内容；MINI 的 probe 使用 `errors="ignore"`。这不是可靠的多格式识别合同，也造成重复检测。

**修改要求**：建立一个 format detector：优先真实魔数/记录结构/声明类型；已知后缀仅用于选择期望解析器，内容不匹配则拒绝；删除重叠的 `is_x_file OR looks_like_x_file` 多次判断；解析错误必须带源文件、格式、行号，不再“试下一个解析器碰碰运气”。

**验收**：错扩展名、同名不同格式、空文件、乱码、损坏 gzip、首行伪造能正确失败，合法 CRD/MINI/native 全通过。

### B-31【P2 / D】台站目录与反射器目录创建程序存在镜像式冗余

**定位**：`programs/station_catalog_create.py:16–63`；`programs/reflector_catalog_create.py:16–63`；`fileio/catalog_sources.py:48–97`。**证据：事实。**

**现状**：两种创建程序具有几乎相同的“文件与 inline 二选一校验→读取→写出→打印”样板；外部源读取也有重复的路径/坐标循环。

**修改要求**：保留独立公开 ProgramSpec、独立物理坐标合同（站点 ITRF/可能速度与历元；反射器 Moon-PA），仅抽取一个内部 `exclusive_source` 校验与参数化执行骨架；不必引入类继承框架或泛化到所有 programs，以免创造新的抽象噪声。

**验收**：两类参数表结构与旧产物内容不变；inline/file/同时给/同时缺/空数据各种模式报错和输出一致；复制粘贴校验代码实际消除。

### B-32【P2 / D+R】配置解析缺模型时应报完整错误链，而不是深处 KeyError

**定位**：`classes/observation/configuration.py:24–32`；`classes/observation_factory.py:569–605`。**证据：事实。**

**现状**：`resolve_model_configs` 对返回 `None` 的类别静默 `continue`，但 runtime 构造随后直接索引 `model_configs["ephemerides"]` 等必需项。最终得到的可能是普通 `KeyError`，难以知道原始 YAML 哪一级缺少模型。

**修改要求**：在解析/装配边界一次校验每个执行模式所需模型清单和来源路径；允许模型 `type: none` 的场景仍须显式声明（如关闭某个可选改正），而不是通过省略配置默默隐含；重用已有 schema 错误类型即可，无需建多个补救层。

**验收**：每个关键类别缺失时错误中含执行 Program、缺失类与期望 YAML 位置；显式 none 模型仍运行并且出现在 resolved model inventory。

### B-33【P2 / R】MPI 单 rank 串行运行不是错误，但不应伪装成真正并行结果

**定位**：`parallel/mpi.py:436–533`；`cli.py:70–74`。**证据：事实。**

**现状**：无 worker 时回到本地 map；CLI 当前已有提示。它是可用的工程便利模式，不会自动改变科学物理模型，但对性能评估及任务预期有影响。

**修改要求**：根据团队偏好选择：`--mpi` 且 rank=1 时严格失败，或者明确支持 `allowSingleRankFallback` 并在运行元数据记录 `execution_mode=serial`。不要删除 worker 初始化、warm-cache、异常传播与结果顺序保证，这些是长期可靠性的根基。

**验收**：1/2/多 rank 三种模式显示有效 worker 数、后端模式，数值字段一致；worker 初始化错误和任务错误不会被调度层吞掉。

### B-34【P2 / R】资源关闭失败不应只留一条低可见度日志

**定位**：`resource_lifecycle.py:12–36`；`config/context.py:145–160`。**证据：事实。**

**现状**：任一 `close()` 抛异常均被捕获并记录 warning，程序仍可能正常结束。保留“关闭其余资源”是正确的，但如果前面科学运行成功、末尾产物写出或内核释放失败，应区别对待。

**修改要求**：累积关闭错误并在 run summary 中登记；主任务成功时，可按严格模式让运行状态失败；主任务已失败时不得让关闭异常覆盖首要原因。保持 finally/上下文管理器，借鉴 SpiceyPy 资源生命周期的清晰边界，不要盲搬其 `kclear()` 全局重置语义。[R4]

**验收**：三个资源中第二个 close 失败，第三个仍被关闭；主失败原因保持优先；发布门槛能读到 cleanup failure。

### B-35【P1 / R】可选 SciPy 依赖必须与轨道执行入口对齐

**定位**：`pyproject.toml` 的 `[project.optional-dependencies].dynamics`；`classes/dynamics/integrators.py:11`；`programs/lunar_orbit.py`。**证据：事实。**

**现状**：SciPy 被列为 dynamics extra，积分器却在模块导入时无条件 `from scipy.integrate import DOP853`。正式安装未开启该 extra 时启动对应轨道 program 将失败。问题并非需要把 SciPy 强迫所有观测软件用户安装。

**修改要求**：明确 install profile：`llr-core` 与 `lunar-orbit`；轨道 program 若未装 extra，在启动之前报出简明缺少 `dynamics` 提示；CI 同时覆盖基础安装与 `[dynamics]` 安装，并在最终环境清单记录确切 SciPy 版本。

**验收**：不带 SciPy 的纯观测入口可执行；动力学入口明确拒绝并提示安装方式；完整安装轨道测试通过。

### B-36【P2 / R】法点预报应区分可见判定原因与采样窗口近似

**定位**：`classes/observation/prediction.py:140–188,191–250`；`programs/llr_observation_prediction_merge.py:32–60`。**证据：事实。**

**现状**：每时刻四个条件（站点仰角、反射器仰角、太阳仰角、月相伸距）以一个 `observable` 布尔值发布；窗口生成本质是采样网格合并，不能作为连续时间精确过境边界。

**修改要求**：保留 `observable` 向后可读性，但增加可审计的逐条件诊断或在报告中逐条件计数，并把窗口的 `gridDefined=true`、步长和边界约定写明；对合并后的每个时间段检验采样规则与输入 stepSeconds 一致。此阶段**不开发**新搜索根算法，只准确陈述现有预报功能。

**验收**：四种单独不通过的样例各给正确理由；跨夜、恰在端点、缺测网格/不同步长结果的窗口定义可复查；错误重叠时间点继续明确拒绝。

### 10.1 软件设置的建议最终形态

每次运行生成**只读的最终有效配置（resolved configuration）**。建议分成四层而不是在运行中到处 `get(default)`：

1. **Scientific models**：星历内核集及相对论比例、EOP 来源/覆盖期、地月定向、测距光时/延迟/位移/偏差模型、动力学每项力/力矩与常数、静态重力场和潮汐系统。
2. **Observations & quality**：CRD/MINI 语义版本、事件类型、σ定义、气象有效期、筛选门槛、法点异常和收敛政策。
3. **Numerics & estimation**：积分器步长/阶数/插值/终止、平差迭代及鲁棒估计与方差分组、参数块与参考系。
4. **Execution & output**：串行/MPI、线程数、日志、进度、目录、输出图表；与科学 fingerprint 分开。

**运行产物应同时保存**：原配置摘要、有效配置、科学输入文件 SHA-256、程序/本地扩展版本、EOP 质量覆盖、每模型开关、参数名/单位/时段、数值算法设置、收敛与失败计数、输出文件哈希及科学兼容指纹。这样 GROOPS 的可重跑性、Orekit 的资源上下文与 SpiceyPy 的核管理优点都能落到 LunarOps 当前能力上。

**比较单位建议**：以秒（两程光时）、米（单程 O−C/坐标）、角秒/毫角秒（地月定向）、米每二次方秒（加速度）、无量纲（四元数/正规方程相对误差）分别报原始差值、RMS、最大绝对差、发生历元与记录 ID。各自数值阈值必须先由已有可靠基线和学科误差预算批准，不可为使测试变绿临时扩大。

### 12.1 可发布与不可发布结果的界限

**允许保存为诊断，但不得宣布正式通过**：法点格式歧义无法解决、星历清单不明、EOP 必要字段缺失、光时不收敛、平差秩亏或终止原因为达到最大迭代、动力学数值失稳。

**可以正式通过**：完整科学输入 manifest 一致，数据拒绝率与原因有记录，观测公式/时标/单位可追，估计收敛且秩与协方差正确，轨道/自转步长一致性经验证，所有核心结果可由同配置重放。

## 13. 不在本次范围内的事项

本次审计**不实现**变分方程、动力学参数解算、LLR 观测模拟；也不新增轨道自适应积分器、全新 EOP 时变估计器、CRD 任意 epoch-event 转换算法、完整 ICGEM 时变力场求值器。若当前代码无法可靠支持某个输入版本，优先**严格拒绝+说明限制**，而不是在审计阶段实现一套未经物理校验的新模型。
